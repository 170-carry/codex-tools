# Codex Tools 客户端接入与运行诊断实施计划

本计划覆盖客户端接入引导、故障诊断和模型可用性，目标是让用户完成「选账号、接客户端、验证调用、查看故障、恢复配置」的完整流程。P0 完成可验证的接入和诊断，P1 增强配置冲突处理、故障恢复和模型能力维护。本轮交付计划及现有 issues 的修复；下列新增模块单独实施，不视为已经完成。

基线为 v3.0.3，提交 `689c266`。桌面前端继续沿用原版与精简版布局、现有翻译与 Tauri 命令边界；代理核心继续供桌面及 Linux proxyd 复用。

## 客户端接入引导

### P0 接入流程和验证

新增 `ClientSetupDialog.tsx`、`useClientSetup.ts`、纯数据模板 `clientSetupTemplates.ts` 和共享类型 `ClientSetupStatus`。入口放在代理服务区，两种布局复用同一向导。首批提供 Codex App/CLI、CC Switch、Magpie 和通用 OpenAI 兼容客户端。

1. 选择客户端与地址范围，检测代理是否启动、是否存在允许参与反代的账号。
2. 选择已有 Key 或显式创建专用 Key，复用原有 Key 管理，不扩大现有权限。
3. 展示协议、地址和允许的模型。Codex 复用原有绑定及备份；其他客户端先提供配置片段和操作步骤。
4. 提供独立的「发送测试请求」动作，说明会消耗少量额度。通过实际代理入口发送固定小请求，关联诊断请求 ID，并验证响应协议和正常结束事件。
5. 分别展示「配置已生成」「配置已写入」「代理测试通过」「已观察到客户端请求」。代理自测通过不能冒充真实客户端接入成功。

后端新增 `proxy_service/client_setup.rs`，提供只读预检和有明确目标的测试命令。测试必须经过同一套 Key 权限、模型校验、候选路由及协议转换，不能维护第二套转发实现。测试入口只接受本工具管理的地址和 Key 标识，避免任意 URL 请求。

验收覆盖代理未启动、无可用账号、Key 禁用、模型不在白名单、协议错误、超时和成功流。取消向导不修改配置；绑定失败保留恢复入口；测试报告不包含 Key、令牌或原始提示词。

### P1 导入和配置变更保护

- 对接 CC Switch、Magpie 已公开的导入协议，生成预览后由用户触发导入；采用专用 Key，避免把主 Key 写入公开链接。
- 为 Codex 绑定新增配置变更预览和文件版本校验。保存时若文件已被其他工具修改，返回冲突并保留当前文件，不以旧快照覆盖。
- 执行后回读配置，展示实际地址、模型目录和需要重启的客户端。恢复只撤销本工具负责的字段，保留绑定后新增的无关配置。
- 不把进程存在、配置文件存在或 `/health` 成功解释为客户端调用成功。

验收使用临时配置目录覆盖保留注释、并发修改、备份恢复、用户修改后恢复、重复绑定和目录同步。不得写入测试人员的真实 Codex 配置。

## 故障诊断

### P0 请求记录和可解释的切换

新增 `proxy_service/diagnostics.rs` 和前端 `ProxyDiagnostics.tsx`。每个请求生成独立 ID，贯穿协议转换、候选账号尝试与流结束。记录客户端 Key 标识、路由、请求模型、实际模型、候选账号 ID、开始时间、耗时、结果和脱敏错误类别。

复用 `classify_retriable_failure`，为每次尝试输出结构化结果。区分连接失败、鉴权失败、额度耗尽、限流、模型受限、上游错误、客户端取消、流截断与成功完成。HTTP 200 只表示收到响应头，正常结束事件到达后才标记请求成功。

首版使用进程内有容量上限的环形记录，仅保留最近 1000 条；列表默认读取最近 50 条，以游标分页，手动查看时刷新。诊断导出使用脱敏 JSON，不记录提示词、工具参数、图片、完整上游响应或凭据。无需新增 SQL 或扫描用户会话数据库。

UI 展示「尝试账号 A → 原因 → 尝试账号 B → 最终结果」，提供复制请求 ID、查看账号状态和相应恢复入口。复用现有用量图表作为统计入口，避免重复累计调用数和 Token。

验收用本地模拟上游验证 401 刷新、429、5xx、模型拒绝、超时、失败后成功、SSE 缺少结束事件及客户端中断。测试请求和正式请求采用相同诊断生命周期。

### P1 冷却和恢复探测

新增 `proxy_service/account_health.rs`，以稳定账号身份维护健康状态及冷却截止时间。尊重有效且有上限的 `Retry-After`，并为网络错误及服务错误采用有上限的退避；鉴权失败和模型权限不足分别处理，模型受限不隔离账号的所有模型。

冷却结束采用单请求探测恢复，防止并发请求同时探测。没有健康候选时返回明确诊断。已经向客户端发送有效流内容后不自动重放整条请求，避免重复输出或重复工具调用。切换账号不保证能够恢复已中断的有状态会话。

健康状态只影响代理候选，保持手动账号切换语义；与顺序模式会话绑定、优先级策略的先后关系通过测试固定。账号删除或凭据替换时清理相关状态。持久化诊断属于后续独立变更，如需要 SQL，先审计索引、保留期、查询上限和写入批次，再用隔离测试库验证。

## 模型可用性

### P0 分离目录支持和账号验证

新增 `proxy_service/model_availability.rs`、共享类型 `ModelAvailabilityEvidence` 和前端模型状态展示。目录、全局开关、Key 权限与账号可用性分别计算，不混成一个布尔值。

| 状态 | 证据 | 用户可执行的动作 |
| --- | --- | --- |
| 代理支持但未验证 | 内置目录或已通过格式校验的供应商目录 | 发起一次显式验证 |
| 已验证可用 | 指定账号和模型的正常请求完成记录 | 查看验证时间及对应请求 |
| 模型受限 | 指定账号返回可识别的模型权限错误 | 更换账号或模型 |
| 暂时无法验证 | 网络、限流、额度或授权错误 | 查看具体原因并重试 |
| 当前策略禁用 | 全局模型开关或 Key 权限 | 跳转相应设置 |

复用模型别名归一化、`ensure_api_proxy_key_allows_payload`、目录过滤及 P0 诊断事件。验证必须固定候选账号，禁止自动回退成功后给原账号标记可用；同时保存请求模型和实际模型，Relay 模型映射不得被误判为原模型可用。

证据携带账号 ID、规范化模型、端点／配置版本、观测时间和过期时间。凭据替换、模型映射或端点修改后使旧证据失效；未知状态保留为未知。模型列表刷新不触发批量推理，不自动扩大 Key 白名单。

验收覆盖别名、受限 Key、Relay 模型映射、回退到其他账号、过期缓存、授权变化和不同 API 的流结束。当前 Luna issue 的错误记录可由此定位，但不能在缺少原始故障证据时宣称已修复。

### P1 目录刷新和客户端同步

- 对提供模型列表的 API 账号显式获取并缓存目录，保留内置兼容元数据和离线回退；供应商返回某模型不等于代理已支持其协议。
- 新模型先进入待验证状态，经过协议、推理参数、工具调用及流事件兼容检查后再开放。
- 展示目录来源、更新时间及同步结果，复用 `sync_bound_codex_catalog` 更新本机绑定。
- 检测到客户端仍需重启时展示动作及影响，不能自动中断正在运行的任务。

## 实施顺序与交付拆分

| 变更 | 范围 | 前置依赖 | 完成条件 |
| --- | --- | --- | --- |
| 1 | P0 结构化请求诊断后端 | 无 | 成功、失败、回退、流截断可通过请求 ID 追踪 |
| 2 | P0 诊断页面与脱敏导出 | 1 | 两种布局可查看同一诊断，无凭据或提示词泄漏 |
| 3 | P0 模型状态与定向验证 | 1 | 不把目录存在或账号回退误报为模型可用 |
| 4 | P0 客户端接入向导 | 1、3 | 从配置到测试再到真实客户端请求的状态分别可验证 |
| 5 | P1 健康状态与恢复探测 | 1 | 冷却并发、恢复及不可重放流场景通过回归 |
| 6 | P1 导入、配置保护及目录刷新 | 3、4 | 冲突不覆盖，回读可验证，白名单保持原有权限 |

每个变更独立完成针对性 Rust／前端测试、两种布局静态渲染、生产构建和 lint。涉及 UI 交互时增加浏览器回归；涉及平台行为时区分 macOS、Windows 原生验证与模拟验证，不以模拟结果替代原生结果。
