# 代码统计与每日提交日历

「代码统计」位于导航第一位，启动时默认打开；Ctrl/⌘+1 也可返回此模块。本功能直接在桌面端读取 Git，不依赖 Python，也不依赖原来那份 HTML 的磁盘路径。

## 使用

1. 选择本地目录或填写远程 Git 克隆地址，点击「添加」。本地支持单个仓库、bare 仓库和包含多个项目的目录；可添加多个来源。远程支持 HTTPS、SSH/SCP 和 `file://` 地址。
2. 按需展开「统计规则」：设置邮箱合并/重命名、单休/双休、低行数提醒；排除人员在独立的「排除人员」区域设置。相同显示名的邮箱合并为同一人。默认不携带任何公司的人员数据。
3. 已配置仓库后，默认打开程序自动更新，并在运行期间每 15 分钟更新；也可点击「生成 / 更新日历」立即刷新。开启同步时获取远程分支与标签并补全浅克隆；取消勾选则读取本地已有历史，报告明确标注未同步。远程来源首次使用仍须下载。
4. 生成后直接显示人员月历，上方提供年月、仓库、人员筛选，以及「布局」（自动、单列、双列、三列）和「紧凑显示」。布局偏好会保存在本机，更新或重启后保留；窗口较窄时自动减少列数以保证可读性。导出 HTML 也保留当前布局。「更多」中可切换颜色、排除大批量变更及导出本月/全历史 CSV；顶部可保存独立 HTML。仓库设置默认收起，点击「仓库设置」修改；汇总与统计说明在月历底部展开。

自动更新：在「仓库设置」顶部修改打开时更新开关及间隔（关闭、5、15、30、60 分钟），选择后立即保存到本机应用偏好。没有仓库不启动任务，正在编辑设置、合并人员或有未应用修改时暂停；切换模块仍继续计时。每次任务完成后重新计时，不重叠执行，失败保留上一份报告并等待下一周期。电脑休眠时不运行，恢复运行后到期任务最多触发一次；退出程序后停止。更新保留当前年月、仓库、人员筛选与滚动位置。独立导出的 HTML 是静态快照，自动更新仅在桌面程序内运行。

人员合并：生成日历后，点击顶部「人员合并」，按姓名或邮箱查找并勾选同一人的多个账号，填写「合并后姓名」，点击「合并并更新日历」。列表覆盖全部历史，含本月无提交账号。合并按邮箱保存到配置，重新扫描仓库并进行身份与补丁去重，后续更新继续应用。原始作者和邮箱仍保留；需要拆分可在「仓库设置 → 统计规则 → 账号合并 / 重命名」修改或删除对应邮箱规则后更新。无邮箱的历史作者暂不支持此入口。

排除人员：打开「仓库设置 → 排除人员」，搜索并勾选不参与统计的人，合并身份按全部已知邮箱排除。也可手动添加原始姓名或邮箱；姓名规则匹配全部同名作者，忽略大小写。点击「应用排除并更新日历」保存；日历、汇总和导出使用同一排除范围。取消勾选或点击某条规则的「恢复」后再次应用，即可恢复统计。新快照保留完整原始作者目录，排除后重启也能找到该人员；旧快照先显示可识别人员和已有规则，更新一次后补齐。原 Git 记录不变。

远程私有仓库沿用系统 Git 凭据管理器或 SSH 密钥，不接受嵌在 HTTP 地址中的用户名、密码或令牌。不弹出交互式登录提示；应先在终端确认可以访问该仓库。Git 须已安装并在 PATH 中。

扫描遇到 `.git` 文件/目录或 bare 仓库后停止向该仓库内继续递归，以免把依赖中的仓库自动纳入；需要时可单独添加内嵌仓库。跳过常见依赖和构建目录。目录链接按真实路径去重。共享 origin 的克隆归为同一仓库，仍读取各个克隆的本地可达历史。同一远程的不同协议在 host、port、路径一致时归并。

## 统计口径

- 使用 committer date，以北京时间（UTC+8）汇总。读取所选仓库全部可达分支与标签，可能包含未推送提交，不是服务端的推送时间。
- 排除 merge；按归并身份和 SHA 去重，文件变更统计相同的候选再比较稳定 patch-id。全部仓库跨仓库去重，单库仅库内去重，各仓库计数之和可能更大。无法判定全部语义等价迁移或原创性。
- 延续旧日历的源文件扩展名及依赖/构建排除规则，包括 Python、Java、TS/JS、Vue、C/C++、C#、Go、Rust、Kotlin、SQL、HTML/CSS、Shell、PowerShell、BAT、微信小程序和 XML。`.mjs`、笔记本、文档等尚未纳入。二进制不计行数。大批量变更为单次超过 10,000 行或 100 个源文件。
- 无提交的当月人员卡片隐藏。年份和月份位于姓名前面。默认每周周日休息；中国官方放假/调休优先。已迁入 2022—2026 年的安排与来源；其他年份显示「安排未核对」，不作低行数判定。
- 默认工作日新增＋删除小于 500 行标记「无效提交」，500 行不标记；休息日、假期及未统计日期免判定。阈值可调整，0 关闭。它是用户设定的提示，不能单独用于判断质量、考勤或工资。

## 数据与故障

配置、上次成功报告、上次备份和远程 bare 克隆保存在应用数据目录下的 `git-activity`。配置导入是本机 JSON 文件，格式参见 `src/features/git-activity/types.ts` 的 `GitActivityConfig`。不向服务端上传统计结果。

扫描、认证、fetch、读取或去重失败时保留上一份报告。可取消正在运行的任务，阻止重复启动。单次 Git 操作超时为 10 分钟。失败的初次下载不会成为正式缓存，可能留下未被 `.repo` 完成索引引用的下载目录供排查；后续使用新目录重试。成功后只发布小型缓存索引，避免 Windows 文件索引器占用 Git 目录导致重命名失败。程序只执行 Git 读取、clone 和 fetch，不 checkout、pull、reset 或 push。

## 开发和验证

前端模块：`src/features/git-activity`；Rust 采集：`src-tauri/src/git_activity.rs`；桌面命令：`git_activity_commands.rs`。

```text
npm ci
npm run build
npm run lint
npm test
cargo test --manifest-path src-tauri/Cargo.toml --bin git-calendar
npm run tauri -- build --no-bundle
```

Windows 使用 MSVC Rust 工具链和 Visual Studio C++ 构建工具；如果系统默认 GNU 工具链，可在 Cargo 命令中指定 `+stable-x86_64-pc-windows-msvc`，或设置该次构建的 `RUSTUP_TOOLCHAIN` 环境变量。

本次本地交付采用 `npm run tauri -- build --no-bundle --config src-tauri/tauri.git-activity.conf.json`：应用名为 **Codex Tools Git**，使用独立应用标识，避免被正在运行的原版单实例进程拦截。该配置关闭上游自动更新地址，避免安装原版更新后覆盖定制功能；原版默认构建配置保持不变。

Windows 安装包使用同一配置构建：

```powershell
$env:RUSTUP_TOOLCHAIN='stable-x86_64-pc-windows-msvc'
npm.cmd run tauri -- build --bundles nsis --config src-tauri/tauri.git-activity.conf.json
```

安装包输出到 `src-tauri/target/release/bundle/nsis`。中文 NSIS 向导安装到当前用户，可创建快捷方式；缺少 WebView2 时联网安装运行时，Git 仍需预先安装并加入 PATH。安装版和便携定制版共用 `com.carry.codex-tools.git-activity` 应用数据目录，安装前退出旧定制版即可沿用配置及统计快照。包内不包含公司的仓库、账号合并名单或登录凭据。定制安装包不生成上游更新签名，也不连接上游更新地址。

浏览器交互回归：启动 Vite 于 5199，运行 `node scripts/check-git-activity.mjs`。需要 Playwright 和 Chrome；可通过 `CODEX_TOOLS_PLAYWRIGHT_MODULE` 指定已有 Playwright 的入口。预览夹具是合成数据，不作为真实采集的证明。Rust 测试另行创建真实本地和 file:// 远程仓库验证下载、同步、去重。`node scripts/check-git-auto-refresh.mjs` 使用浏览器虚拟时钟验证自动更新、持久化、编辑暂停、不重叠、失败重试和筛选保持。

可选无界面工具使用同一采集实现：

```text
cargo build --manifest-path src-tauri/Cargo.toml --bin git-calendar
git-calendar config.json cache-directory report.json
```

日历 HTML 对 Git 元数据进行 JSON/HTML 转义，并在无同源权限的 iframe 内显示，避免仓库内容获得桌面命令权限。HTML 不依赖网络资源。
